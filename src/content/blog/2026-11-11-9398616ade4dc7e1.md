Send Xen Orchestra an empty token object and it hands you the first token in the database — and Admin with it. REST auth accepted a non-string token, so the lookup returned whatever came back first. From there: code execution on managed pools and root on the XCP-ng node. Vates says it's already being exploited; grep your logs for authenticationToken=j:%7B%7D. Fixed in XO 6.9.1/6.10.0 and xo-server 5.211.2/5.213.1.
